# ARCHITEKTUR (Pod-Startskript als Gerüst umgesetzt, alles andere geplant)

Keine Ordnerstruktur festgelegt; sie ergibt sich bei der Umsetzung.

- **Pod-Startskript** (Gerüst umgesetzt): richtet einen frischen RunPod-Pod ein – Repo klonen, ComfyUI installieren, Modelle und LoRAs laden, rclone konfigurieren. Liegt im Ordner `pod/` (`pod/start.sh`). Der Startbefehl der RunPod-Vorlage klont das Repo und ruft `pod/start.sh` auf. Alle Schritte laufen über die gemeinsame Funktion `run_step` (Protokoll, Dauer, Fehlerbehandlung; nach dem ersten Fehler werden weitere Schritte übersprungen). Protokoll: `/workspace/logs/start.log`. Bei einem Fehler bleibt der Pod erreichbar (`sleep infinity`, RunPod-Dienste laufen im Hintergrund). Versionen stehen nur in `pod/versions.env`. Bisher enthalten: Repo absichern, Secrets prüfen, ComfyUI installieren (Ziel `/workspace/ComfyUI`, Version aus `pod/versions.env`), GPU-Probe nach der Installation, Modelle laden, LoRAs laden; ComfyUI im Hintergrund starten; rclone installieren (Version und Prüfsumme in `pod/versions.env`) und einrichten (Konfiguration `/root/.config/rclone/rclone.conf`, Remote `gdrive`, Ordner `DreamDeck`), jeweils vor dem ComfyUI-Start; danach Sync-Schleife starten; gemeinsame Pfade in pod/paths.env. Modelle: `pod/models.toml` beschreibt die Modell-Sets (Dateien, Ladeart, Prüfsummen), `pod/models.py` ist der Download-Baustein (Quellen-, Platz- und Prüfsummenprüfung; auch fürs Dashboard gedacht). Welche Sets geladen werden, steht in `pod/versions.env` (`DEFAULT_MODEL_SETS`) und ist per `MODEL_SETS` überschreibbar. LoRAs: `pod/loras.toml` enthält nur Civitai-Versionsnummern; der Befehl `loras` von `pod/models.py` holt Dateiname, Größe und Prüfsumme über die Civitai-API und lädt über denselben Download-Weg wie die Modelle (Token nur aus `CIVITAI_TOKEN`).
- **ComfyUI headless** (Start umgesetzt): läuft ohne eigene Oberfläche als Bildmotor und wird über die ComfyUI-API angesprochen. Lauscht nur auf 127.0.0.1:8188. Bilder liegen unter `/workspace/output` (außerhalb von `/workspace/ComfyUI`, weil ein Versionswechsel diesen Ordner löscht). Protokoll: `/workspace/logs/comfyui.log`.
- **DreamDeck-Backend** (Gerüst umgesetzt): vermittelt zwischen Oberfläche und ComfyUI-API, verwaltet Verlauf und Metadaten, liest Secrets nur aus Umgebungsvariablen. Technik: Python, FastAPI, uvicorn, httpx; ComfyUI per HTTP (Aufträge, Bilder) und Websocket-Client (Fortschritt); Fortschritt an die Oberfläche per Server-Sent Events, sonst fetch; nur DreamDeck von außen erreichbar, ComfyUI nur intern; Tests direkt auf dem Pod; bis zur Freigabe lauscht das Dashboard nur auf 127.0.0.1 (Zugriff per SSH-Tunnel); neuer Code kommt mit einem neuen Pod (Vorlage auf dem Etappen-Branch); gestartet wird das Dashboard von `pod/start.sh`. Liegt in `dashboard/` (`app.py`, Einstellungen nur über `config.py` aus `pod/paths.env`, Port `DASHBOARD_PORT`); Abhängigkeiten fest gepinnt in `dashboard/requirements.txt`, eigene venv auf dem Pod (ab 2c). Workflows liegen als API-JSON in `dashboard/workflows/`; `workflow.py` setzt Werte über die Knotentitel und baut die LoRA-Kette (0–6) ein. Aufträge über `POST /api/generate`; Bilder landen im Monatsordner `JJJJ-MM/`. Fortschritt: eine dauerhafte Websocket-Verbindung zu ComfyUI (`events.py`), übersetzt in Ereignisse (warteschlange, start, fortschritt, fertig, fehler, verbindung) und per `GET /api/events` (Server-Sent Events) an alle Browser verteilt.
- **Oberfläche** (Gerüst umgesetzt): nach Entwurf „Variante B“ – Pipeline-Boxen 1–5, Prompt-Leiste, Bühne mit Verlauf, Einstellungsseite (zeigt nur den Status der Secrets). Technik: schlichtes HTML/CSS/JS ohne Build-Schritt, ES-Module statt globaler Variablen; Alpine.js (fest im Repo, Version in Etappe 2 gepinnt) für Step-Boxen und LoRA-Liste; Live-Fortschritt per Server-Sent Events. Liegt in `dashboard/static/` (`index.html`, `css/dreamdeck.css`, `js/app.js`), Alpine.js 3.17.5 fest im Repo unter `static/vendor/` (sha256 geprüft).
- **rclone-Sync** (umgesetzt): `pod/sync.sh` kopiert (copy, nicht move) `/workspace/output` nach `gdrive:DreamDeck`. Die Schleife läuft alle 30 s mit `--min-age 15s` und startet mit dem Pod; der manuelle letzte Sync läuft ohne Mindestalter. `flock` verhindert Überschneidungen. Protokoll: `/workspace/logs/sync.log`.
- **LoRA-Liste** (geplant): Datei im Repo ohne Token; der Pod lädt die Einträge beim Start über das Civitai-Secret.

## Secrets (geplant)

- Die Secrets liegen als RunPod-Secrets im Konto; die Pod-Vorlage gibt sie beim Start als Umgebungsvariablen weiter.
- Das Startskript nutzt `GITHUB_TOKEN`, `CIVITAI_TOKEN`, `DREAMDECK_DRIVE_TOKEN`, `DREAMDECK_DRIVE_CLIENT_ID` und `DREAMDECK_DRIVE_CLIENT_SECRET`.
- Das Dashboard nutzt `DASHBOARD_PASSWORD` und später (optional) `ANTHROPIC_API_KEY`.
- Im Repo stehen nur die Namen, nie die Werte. Details und Begründungen: NOTIZEN.md.
